# DES.4 Everyday Language Ergonomics

- Status: design proposal with a follow-up backlog; nothing here is implemented
  or approved as a language contract by this document.
- Date: 2026-09-23
- Base: `main` after API.1 (interface manifests), SX.27 (generated accessors),
  and APP.11 (the four applications as acceptance fixtures).
- Owner decisions required before dependent implementation are listed in §11.

## 1. Question

Four everyday applications were written in Jacquard as delivered (dice coach,
picnic planner, rota optimizer, formula notebook; `demos/applications/`, with
the authors' journals under the research `projects/` tree). Their sources are
correct, checked, and native-buildable, and their journals report an empty set
of unresolved diagnostics. What they report instead is *burden*: the same shape
of code written many times. This design asks which bounded changes remove that
burden while keeping the 27-form kernel, the permanent `.jqd` carrier,
`HASH_V0`, and every existing identity unchanged.

The measure throughout is task clarity, code burden, and tooling complexity,
not character count. A shorter spelling that hides evaluation order, identity,
or authority is a loss.

## 3. Evidence From The Applications

Counted on the imported fixtures (`demos/applications/`), which equal the
journals' sources by manifest.

**Selectors written by hand.** rota-optimizer `model.jac:37-73` defines 11
one-clause selector functions (`rota.staff-id`, `staff-name`, `staff-limit`,
`shift-id`, `shift-label`, `people`, `shifts`, `rest`, `weight`,
`solution-score`, `solution-assignments`); formula-notebook `model.jac:25-68`
defines 15 (`nb.cell-name`, `cell-source`, `cell-expr`, `cell-deps`, `cells`,
`edges`, `cache`, `hits`, `computed`, `current`, `undo-list`, `redo-list`,
`outcome-book`, `accepted?`, `outcome-message`). Every one is a two-line
`match` that SX.27 now generates (`rota-staff.id`, `nb-snapshot.cells`, …);
`test/cli/applications.t` pins that the generated and hand-written versions
agree. Twenty-six definitions, roughly fifty lines, exist only to read a
field.

**Whole values rebuilt to change one field.** `NbSnapshot` has five fields.
`model.jac:209` rebuilds all five to add one to `hits`; `:225` rebuilds all
five to change `cache` and `computed`; `:295` rebuilds all five to replace
three. `NbBook` (three fields) is rebuilt at `:361`, `:375`, `:387`.
`RotaStaff` has six fields; `fixtures.jac:159-175` matches all six and rebuilds
all six to change `available`, and `tests.jac:153-160` rebuilds positionally.
Burden compared: the notebook carries 15 selectors (30 lines) and six
rebuild sites of five to seven lines each; the rota carries 11 selectors (22
lines) and two rebuild sites of 17 and 8 lines. The notebook's burden is
spread over many small sites, the rota's concentrated in wide ones; both
disappear under the same two generated forms.
The journals name this directly: "reading and rebuilding staff records needed
many small selector functions and constructor matches" (rota
`DEVELOPMENT.md:134-136`); "accessor functions and rebuilding five-field
snapshots are repetitive without records or update syntax, and the formatter
expands that code a lot" (notebook `DEVELOPMENT.md:72-73`).

**Predicate chains.** rota `model.jac:279-290` validates a staff record with a
right-nested `bool.and(bool.and(int.gte?(id, 0), int.lte?(id, 99)),
bool.and(…))` seven levels deep. The model uses `bool.and` on 33 lines and
`int.gte?`/`int.lte?` 29 times. The journal does not complain about prefix
arithmetic itself (it praises exact integers, `DEVELOPMENT.md:125`) and reports
one wrap-around bug in a subtraction (`:84-86`), which is a numerics question,
not a syntax one.

**Composition.** Every README assembles an entry point with `cat`; the notebook
README states "Jacquard has no imports, so source composition uses
concatenation" (`README.md:119`); rota's journal lists concatenation as
remaining friction (`DEVELOPMENT.md:141-142`). Both applications prefix every
name by hand. No collision was reported, because the prefixes are disciplined.

**Diagnostics.** The one editor-facing complaint (notebook
`DEVELOPMENT.md:29-33, 77-79`: one malformed declaration buried the real error
under a cascade) is fixed by APP.8. The remaining friction is in the native
backend and stdlib (interpolation arity cap, `text.to-int`, `read-line` at end
of input), already tracked by the APP tasks.

The two demos named by the task add no reconstruction and no arithmetic beyond
`real.add`/`real.mul`/`real.sub` and `match real.lt?(…) { | True -> … }`
(`demos/inference/clarifying-question.jac:4,21,58`), and one positional
four-field pattern used to read one field
(`demos/case-studies/release-risk/model.jac:100-101`, now `assessment.decision`).

Conclusion: the burden is concentrated in *reading and rebuilding nominal
values*, then in *boolean predicate chains*, then in *composition*. Arithmetic
spelling and editor diagnostics are not where the evidence points.

## 4. User Scenarios

1. **Exclude a person from a rota fixture.** Take a `RotaStaff`, produce the
   same person with `available` emptied. Today: a six-field pattern and a
   six-field construction (17 lines). Wanted: one line that names the field.
2. **Record a cache hit.** Take an `NbSnapshot`, produce it with `hits + 1`
   and everything else unchanged, without listing the other four fields.
3. **Recalculate after an edit.** Produce a snapshot with new `cells`,
   `reverse`, and `cache` while keeping `hits` and `computed`, and be certain
   each new value is evaluated exactly once, in source order, before the
   value is built.
4. **Validate a record.** State "id in 0..99, name non-blank, limit in 0..14,
   no duplicate availability" as a flat list of conditions, not a
   right-nested tree.
5. **Assemble the application.** Run, test, and build the notebook from its
   six source units without `cat`, with `nb.`-prefixed names that do not
   collide with a library that also defines `cells`.
6. **See why a name is unknown.** Calling `reply.value` when `value` is
   labeled on only some constructors should say so, not report a bare E0301.

## 5. Proposal A — Nominal Field Updates (the decision task 220 waits on)

### A.1 Recommendation: generated setters first, a `with` form second

**Phase 1 (SX.28a): generated setters.** For every label that already earns an
accessor under SX.27, lowering also generates one ordinary pure `DefTerm`

```
<type-kebab>.with-<label>   -- (T, FieldType) ->{} T for a monomorphic T
```

whose body is the explicit twin

```jacquard
rota-staff.with-available(value, field) = match value {
  | RotaStaff(id: a, name: b, skills: c, available: _, limit: d, preferences: e) ->
    RotaStaff(a, b, c, field, d, e)
}
```

with `surface-generated` provenance (hidden by the printer, `fmt`, and
`--print-sigs`, exactly like accessors), a `call-abi-v1` companion
`(positional, named value)` so `rota-staff.with-available(person, value: Nil)`
reads at the call site, and E1241 extended to the `with-` names. The
signature is whatever the twin infers: for a parametric type the updated
field's parameter is fresh, `pair.with-left : forall a b c. (Pair a b, c) ->{}
Pair c b`, so `pair.with-left(MkPair(1, "a"), 2.5)` is `Pair Real Text` — a
type-changing update falls out of the twin without a rule.

Scenario 1 becomes `rota-staff.with-available(person, Nil)`. Scenario 2 becomes
`nb-snapshot.with-hits(snapshot, add(nb-snapshot.hits(snapshot), 1))`. Scenario
3 chains three setters; each argument is evaluated once, in source order,
because each is an ordinary call:

```jacquard
nb-snapshot.with-cache(
  nb-snapshot.with-reverse(nb-snapshot.with-cells(snapshot, cells), reverse),
  cache,
)
```

**Phase 2 (SX.28b): the `with` form.** The decision is that both phases are
task 220's scope, in this order; Phase 2 is not gated on further evidence.
Two of the six notebook rebuild sites already change two or three fields
(`model.jac:225`, `:295`), and a three-deep setter chain reads its updates
inside-out, against this document's own clarity measure, so the syntax is
justified today:

```jacquard
NbSnapshot(snapshot with cells: cells, reverse: reverse, cache: cache)
```

elaborating to `let s = snapshot; let u1 = cells; let u2 = reverse; let u3 =
cache; match s { | NbSnapshot(cells: _, reverse: _, cache: _, hits: h,
computed: c) -> NbSnapshot(u1, u2, u3, h, c) }`, that is, the same twin as the
setter chain with the intermediate values elided. It hashes as its twin, as
named calls do (D76). Its printer needs a `field-update` provenance to
round-trip, and `with` must become a reserved word (§11).

Why this order: Phase 1 is the elaboration target and removes every
reconstruction site in the applications with zero new syntax, no parser,
printer, formatter, or keyword work, and no new diagnostic codes; it reuses
SX.27's generation, provenance, hiding, and collision rules; the setters are
ordinary exports that appear in `interface-v1` manifests and can be named in
calls. Phase 2 then has a single, already-tested meaning to elaborate to, and
its acceptance is stated against the same sites (§13). Single-field updates
may keep using the setter; the formatter does not rewrite one into the other.

### A.2 Eligibility and refusal (both phases)

- A label earns a setter exactly when it earns an accessor: carried by every
  constructor, uniformly typed, valid as a symbol, not colliding. A label on
  only some constructors has neither; write the match.
- A sum type with a uniformly carried label gets a *total* setter (one clause
  per constructor, like the accessor). Phase 2's `with` names a constructor,
  so on a sum type it elaborates to a one-clause match; the existing
  exhaustiveness check refuses it (the same diagnostic a partial match gets),
  and the message must say "use `<type>.with-<label>` for a total update".
- Unknown or duplicate labels in a `with` form are the constructor-pattern
  boundary's E0305/E0306, at the label's span.
- Hidden constructors: the elaboration is a constructor pattern plus a
  constructor call, so a setter or `with` is legal exactly where those are;
  TYPE.1 (218) decides that boundary once and both forms inherit it. A setter
  generated inside the defining scope stays usable outside it, which is the
  "validated public function" TYPE.1 wants.

### A.3 Alternatives considered

- **Structural records** (`{ v | cells = e }` over row types): the cleanest
  syntax, but it needs a new kernel form or a record encoding, changes what a
  type is, and gives every labeled type two identities. Rejected while the
  27-form kernel and `HASH_V0` are frozen; `docs/ast.md` §5.3 already defers
  true records.
- **Field-access syntax** (`p.left`): excluded by D37, which reserves dotted
  names as atoms; the accessor `pair.left(p)` is the sanctioned spelling.
- **`with` first, no setters**: every update still needs the parser, printer,
  formatter, keyword, and provenance work before one line of application code
  improves; setters deliver the same twin with none of that.
- **Lenses or a generic `update` function**: needs higher-order label
  reflection the kernel does not have, and hides evaluation order.

## 6. Proposal B — Predicates Over Operators

Keep D28 and D39: no infix arithmetic or comparison operators, no precedence.
The evidence does not show prefix arithmetic as a burden; it shows nested
boolean conjunction as one. Two library additions, no syntax:

- `bool.all : (List Bool) ->{} Bool` and `bool.any : (List Bool) ->{} Bool`
  (list-based, so the native eight-argument ceiling that bounds variadic
  `text.join` does not apply), plus `list.all? : (List a, (a) ->{e} Bool)
  ->{e} Bool` and `list.any?`.
- `int.between? : (Int, Int, Int) ->{} Bool` and `real.between?`, closed
  intervals, arguments `(value, low, high)` with a `call-abi-v1` companion
  `(positional, named low, named high)`.

Scenario 4 becomes

```jacquard
bool.all([
  int.between?(id, low: 0, high: 99),
  bool.not(text.empty?(text.trim(name))),
  int.between?(limit, low: 0, high: 14),
  rota.distinct?(available),
  rota.distinct?(preference-ids),
  list.all?(available, fn (key) -> rota.member?(key, shift-ids)),
])
```

Depth 7 becomes depth 1; every condition is one list item; short-circuit
semantics are *not* implied (all items are evaluated, as they are today in the
nested form, since `bool.and` is a function). The short-circuiting forms
`bool.and-then`/`bool.or-else` (thunked second argument) and `if` already
exist and stay the spelling when evaluation must stop early. Identities: new prelude objects with new hashes; nothing
existing changes.

Alternative rejected: infix `&&`/`||`/`+`/`<`. It reopens D28, needs
precedence and a formatter policy, and the journals do not ask for it.

## 7. Proposal C — Composition Through PKG.1

The design decision for task 217 that this document takes: a **namespace is a
lowering-time name prefix, never a kernel or identity concept.** A source unit
declares `namespace rota` once; every top-level name it introduces is bound as
`rota.<name>` in the store, exactly as the applications spell by hand today,
so identities, `names.jqd`, and D37 are untouched and existing prefixed
sources keep working. A project file lists source units, entry points, pinned
dependencies (by `interface-v1` identity), and exports (by name); resolution
is deterministic in unit order, and a name bound by two units with the same
prefix is a project diagnostic, not a silent shadow. `cat` disappears from
the READMEs. Nothing here needs new task IDs; §12 refines 217's acceptance.

## 8. Proposal D — Editor Feedback Through DX.1

The language server (227) consumes the RF.1 frontend and API.1 manifests.
Two small diagnostics improvements are independent of it:

- **Near-miss hint for ineligible accessors and setters.** `reply.value` when
  `value` is labeled on `Accepted` only: E0301 gains a hint "`value` is a
  field of `Accepted` but not of every `Reply` constructor; match
  `Accepted(value: v)` instead". Same for `with-` names.
- **Generated-name hover.** The server shows a generated accessor or setter
  with its origin label span and the explicit twin, so hidden boilerplate
  stays inspectable.

## 10. Compatibility, Identity, Failure

- Kernel, `HASH_V0`, `.jqd`, store format: unchanged by A1, B, C, D. A2 adds
  surface syntax only; its hash is its twin's.
- New generated names `<type>.with-<label>` follow the accessor rules: a
  file that defines one by hand is E1241, and a same-named prelude or store
  term is shadowed exactly as a hand-written definition would shadow it. The
  prelude already uses the `with-` shape (`option.with-default`,
  `result.with-default`, `net.with-retries`, `governance.with-sequence`), so
  a user type named `option` with a `default` label would shadow
  `option.with-default`; no maintained source declares such a type, and the
  applications define no `with-` names of their own.
- Reserving `with` (A2) breaks any program using `with` as a bare identifier.
  None exists: outside comments and text literals the word appears only
  inside dotted names such as `list.merge-with`, which D37 keeps as single
  atomic tokens, so the keyword cannot clash with them.
- New prelude objects (B) have new identities; nothing is renamed.
- Failure: setters and predicates fail like any call (arity E0803, type
  E0801); `with` on an ineligible type fails at lowering or exhaustiveness
  with the hints above; hidden-constructor use follows TYPE.1.

## 11. Decisions Requiring Owner Direction

1. Approve the `Ctor(value with label: expr, ...)` spelling for Phase 2 (the
   sequencing, setters first, is decided here).
2. Reserve `with` as a keyword now (recommended: cheap while no source uses
   it) rather than at Phase 2.
3. Accept list-based `bool.all`/`bool.any` and closed-interval `between?`
   as prelude additions (they change no existing identity).
4. Confirm "namespace = lowering-time prefix" as the PKG.1 contract.

## 13. Validation And Measurable Acceptance

- The 26 hand-written selectors and the 8 reconstruction sites (six in the
  notebook model, two in the rota fixtures and tests) are replaceable by generated accessors and setters with byte-identical
  demo transcripts and interpreter/native parity (`applications.t`).
- Each rewritten update site evaluates its source value and each new field
  exactly once, in source order: pinned with effect counters in the SX.28
  suite, as D76 pins named-call order.
- `jac fmt` is idempotent on the rewritten models; `hash` of a setter equals
  the hash of its hand-written twin; after Phase 2, `hash` of a `with` form
  equals the hash of its explicit let-and-match twin, and the two multi-field
  notebook sites (`model.jac:225`, `:295`) read as one `with` form each.
- The rota validation predicate's nesting depth drops from 7 to 1 with the
  same truth table on the existing fixtures.
- The readability protocol regression gate is unchanged (no cohort is added;
  the benchmark machinery must still run).
- Non-goals for this cycle: structural records, infix operators, field-access
  syntax, modules with imports, defaults or puns, any kernel form.
